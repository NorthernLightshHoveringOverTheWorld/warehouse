# Склад — PostgreSQL, веб-интерфейс и Docker

Java 17, Spring Boot 3.5, JDBC, PostgreSQL 17, Flyway и HTML/CSS/JavaScript.
Бизнес-правила первого таска сохранены; веб-приложение работает с настоящей БД.
Внешние CDN и отдельная сборка фронтенда не нужны.

## Запуск

Запустите Docker Desktop в режиме Linux containers. В корне проекта:

```shell
docker compose up --build -d
```

Откройте **http://localhost:8080**. Первая сборка скачивает образы и зависимости.
Готовность приложения видна в `docker compose logs -f app`.
PostgreSQL запускается на вашем компьютере в контейнере; отдельная нативная
установка СУБД для этого варианта не нужна.

```shell
docker compose ps
docker compose logs --tail=100 app
docker compose stop
docker compose up -d
```

Данные хранятся в постоянном томе `warehouse_postgres_data`. Перезапуск, `stop`
и обычный `down` сохраняют их. **Не используйте `docker compose down -v` для
обычной остановки: он удаляет том с данными.**

Приложение учебное, локальное, без авторизации. Порты публикуются только на
127.0.0.1. Пароль по умолчанию предназначен для локальной разработки.

## Подключение к БД из pgAdmin, DBeaver или IDEA

| Параметр | Значение |
| --- | --- |
| Хост | localhost |
| Порт | 5434 |
| База | warehouse |
| Пользователь | warehouse |
| Пароль | warehouse_local |

Порт 5434 выбран, чтобы не занимать стандартный 5432 у нативной PostgreSQL.
Для изменения настроек скопируйте `.env.example` в `.env`: доступны
DB_PASSWORD, DB_PORT, APP_PORT. `.env` исключён из Git.
Смена переменной DB_PASSWORD после создания тома не меняет пароль роли в уже
существующей БД: его нужно менять отдельно через SQL.

SQL-консоль:

```shell
docker compose exec db psql -U warehouse -d warehouse
```

Список таблиц: `\dt`, выход: `\q`.

## Запуск Java из IDEA

Оставьте в Docker только БД:

```shell
docker compose up -d db
docker compose stop app
mvn clean package
java -jar target/warehouse-1.0-SNAPSHOT.jar
```

Или запустите `org.example.warehouse.WebApplication` в IDEA с JDK 17+.
Если Maven не в PATH, используйте окно Maven в IDEA.

Для установленной отдельно PostgreSQL создайте базу и роль, затем задайте
переменные перед запуском Java:

```powershell
$env:DB_URL='jdbc:postgresql://localhost:5432/warehouse'
$env:DB_USER='warehouse'
$env:DB_PASSWORD='ваш-пароль'
```

Flyway автоматически создаёт таблицы и хранит историю миграций.

## Функциональность

- Регистрация товаров, поставщиков и покупателей.
- Каталог с остатками, поиск, фильтр наличия, выбор вида и группировка.
- Приём произвольного положительного количества с защитой от переполнения.
- Выдача покупателю с проверкой наличия.
- Поставщики с перечнем товаров, покупатели с историей выдач.
- Общая история, сообщения об ошибках и успешных действиях, адаптивная компоновка.
- Сохранение данных после перезагрузки страницы и перезапуска приложения.

Начните с поставщика, затем создайте товар и покупателя. Примите 12 штук и выдайте 3:
остаток станет 9. Попытка выдать 10 завершится ошибкой без изменения остатка.
Демонстрационные записи автоматически не добавляются.
Редактирование/удаление карточек не входит в исходное задание и не добавлено.

## Архитектура

```text
Браузер → web/WarehouseController → CatalogService / InventoryService
        → application/port → infrastructure/jdbc → PostgreSQL
```

`domain` не зависит от Spring. Контроллер не пишет SQL и не рассчитывает остаток.
`WebApplication` собирает сервисы с JDBC-реализациями через `@Bean`.
В `WarehouseRepository` добавлен `update(operation)`: JDBC-реализация открывает
транзакцию и блокирует строку склада через SELECT FOR UPDATE до сохранения.
Ошибка откатывает и остатки, и историю. Обычные выдачи дописываются без пересоздания старых строк.

Подробности: [База данных](docs/DATABASE.md), [веб-интерфейс и API](docs/WEB.md).
Версия рассчитана на один небольшой склад: изменения сериализуются, состояние
читается целиком. Для большой БД потребуются операции над отдельными остатками и пагинация.

## Первый таск

`Main` по-прежнему запускает консоль с in-memory хранилищами:

```shell
java -cp target/classes org.example.warehouse.Main
```

В Windows: `chcp 65001`. В IDEA можно запустить Main напрямую.
Историческое описание первого этапа — [TASK1.md](docs/TASK1.md).
Текущие команды запуска приведены здесь: веб-JAR запускает WebApplication.

## Проверки

```shell
mvn test
```

Обычный запуск выполняет тесты модели, сервисов, консоли и API. PostgreSQL-тесты
пропускаются, если не настроена отдельная тестовая БД. Создать её один раз:

```shell
docker compose exec db createdb -U warehouse warehouse_test
```

Запустить все тесты в PowerShell:

```powershell
$env:TEST_DATABASE_URL='jdbc:postgresql://localhost:5434/warehouse_test'
mvn test
Remove-Item Env:TEST_DATABASE_URL
```

Если меняли пароль, задайте DB_PASSWORD также для Java.
Интеграционные тесты очищают только warehouse_test и отказываются работать
с именем рабочей БД. Проверяют FK/CHECK, откат SQL-ошибок, сохранение данных,
контракты репозиториев, API и конкурентные поступления/выдачи.
