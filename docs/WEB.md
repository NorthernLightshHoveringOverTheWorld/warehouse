# Таск 3: веб-интерфейс

Статика и JSON API обслуживаются одним Spring Boot на одном порту.
Фронтенд отправляет количество серверу и после успешной операции получает
обновлённые данные. Бизнес-остатки рассчитывает доменная модель Java.

| Метод и адрес | Назначение / тело JSON |
| --- | --- |
| GET /api/products | Каталог |
| POST /api/products | {name, type, supplierId} |
| GET /api/suppliers | Поставщики |
| POST /api/suppliers | {name, contact} |
| GET /api/customers | Покупатели |
| POST /api/customers | {name, contact} |
| GET /api/inventory | Все позиции с остатками |
| GET /api/inventory?available=true | Только положительные остатки |
| GET /api/inventory/groups | Группы по виду |
| GET /api/inventory/{productId} | Остаток одного товара |
| POST /api/receipts | {productId, quantity} |
| POST /api/shipments | {productId, customerId, quantity} |
| GET /api/shipments | Все выдачи |
| GET /api/customers/{customerId}/shipments | История покупателя |
| GET /api/health | Проверка приложения и доступности БД |

UUID передаются строками. Количество — положительный int: дроби и переполнение
отклоняются. Создание карточек возвращает 201, операции — 200, ошибка ввода — 400,
нарушение связей БД — 409, недоступность БД — 503. Ошибка: `{ "message": "..." }`.
Контакт — свободный текст. Ограничения веб-форм: имя 200, контакт 300, вид 100 символов.

## Новые файлы

- WebApplication: запуск и сборка сервисов с JDBC.
- web/WarehouseController: маршруты и DTO запросов с Bean Validation.
- web/ApiErrors: перевод исключений в ответы без раскрытия SQL.
- static/index.html: структура страницы и диалоги.
- static/styles.css: единый стиль, состояния элементов, мобильная компоновка.
- static/app.js: HTTP-запросы, фильтры, отображение и формы.

Пользовательский текст выводится через textContent или HTML-экранирование.
Отправка блокируется на время запроса. Ошибка не очищает введённую форму.
Если операция сохранена, а обновление списка не удалось, интерфейс отдельно
сообщает об этом. UUID остаются внутри приложения, в основных таблицах они не выводятся.

## Демонстрация

1. Создать поставщика, товар и покупателя.
2. Принять 12, затем 8: остаток 20. Выдать 3: остаток 17.
3. Выдать 18: ошибка, остаток и история прежние.
4. Проверить поиск, группировку, фильтры, справочники, историю одного покупателя.
5. Перезагрузить страницу и перезапустить приложение: данные сохраняются.
6. Проверить пустые поля, 0, отрицательное, дробное и слишком большое количество.
7. Проверить узкое окно и управление формами с клавиатуры.

Авторизация, публичное размещение, пагинация и редактирование/удаление карточек
находятся вне исходного задания. Ошибки конкурентных операций защищены транзакциями БД.
